# RRC 使用说明

通过 `/rrc` 打开设置。设置按角色保存，修改即时生效。

支持 retail 和 `_forever_`（接口号 16001）。forever 沿用 retail 接口实现，但不加载 DK 沸点监测和集合石屏蔽模块；对应左侧入口置灰、不可点击，默认打开姓名版 Debuff 页面。即使导入的旧设置开启了 DK 监测，在 forever 中也会强制关闭。

## 文件结构

- `ReRan's customlizations.toc`：插件信息及加载顺序。
- `Core.lua`：公共 UI、数值和 SharedMedia 辅助方法。
- `Modules/`：八个功能的运行实现。
- `Config.lua`：配置页面、数据库初始化和 `/rrc` 入口。
- `docs/`：使用说明与历史调研资料，不参与游戏内加载。

加载顺序为 Core → 功能模块 → Config。外部集合石助手及个人数据仍放在魔兽目录外。

## 5. 集合石屏蔽

点击“读取当前列表并输出”后截图，打开魔兽目录外的 RRC 集合石助手（RRC_MS.exe），选择本批截图，识别后复制并导入字符串。页面保留操作结果提示。

## 6. 自定义冷却管理器音效

1. 停用 CooldownManagerCustomSounds，然后 `/reload`；RRC 不会自动禁用或修改它。
2. 勾选第六页的“开启”（默认关闭）。
3. 在暴雪冷却管理器中编辑声音提醒，选择 SharedMedia 子菜单中的音效；右侧按钮可试听。
4. 按暴雪原有流程确认提醒、保存布局。关闭本功能后，自定义提醒停止播放，已保存的名称和编号保留。

媒体由插件注册到 LibSharedMedia-3.0，不按文件夹扫描；该库也可以由其他插件提供。音效使用 Master 声道，受游戏总音量及静音控制。媒体暂时缺失时保留名称，恢复注册后无需重建提醒。

暴雪右键列表中的自定义提醒名称可能为空，编辑器内仍可显示完整名称。跨角色或账号导出暴雪布局不会携带 RRC 的名称映射，目标角色需重新选择音效。

## 7. 队友打断监视

默认关闭，只在非团队的小队中显示自身和队友的打断计时条。

- 可选择条材质、文字字体，调整计时条长度、高度、字体大小。
- 文字和计时横坐标偏移分别调整姓名与时间文本的水平位置。
- 时间小数位数支持 0、1、2 位；无观察中的冷却时显示“就绪”。
- X/Y 调整整组计时条左上角相对屏幕中心的位置。右键滑条数值可精确输入，Enter 提交，Esc 取消。
- “显示角色服务器名”默认不勾选：关闭显示 `角色1`，开启显示 `角色1-服务器1`。这只影响条上的文字，不改变内部成员身份匹配。
- 外观与位置设置不清除正在进行的倒计时，关闭设置窗口或切换页面也不停止监视。

材质与字体使用已注册的 SharedMedia 资源；没有可用资源时回退默认样式。

队友冷却来自技能表估算，不等于真实同步，天赋、宠物和重置可能造成差异。可读施放直接计时，隐藏施放使用敌方中断与暴雪统计辅助推断；推断以 `~` 标记，图标悬停保留说明。隐藏技能 ID 的空踢可能漏记，“就绪”不证明刚入队时技能真实可用。

## 8. 自动邀请

retail 和 forever 均提供此功能，设置按角色保存，默认关闭，初始字符串为 `RRC-Inviteme`。

1. 在右侧页面勾选“启用”。点击“添加字符串”增加输入框，点击每行“删除”移除该行；可以全部删除。
2. 输入框修改即时保存。监视角色密语、战网好友密语和公会频道聊天，三种来源共用同一组字符串；只有整条内容与任意一个非空字符串完全相同才邀请。大小写、下划线、连字符及首尾空格均严格区分，不使用模式或子串匹配。
3. “导出密语”使用第一行（不是第一条非空行）生成 `/w 当前角色名-服务器名 第一条字符串`，显示在右侧底部的复制文本框中并自动选中，可按 Ctrl+C 复制；不打开聊天输入框，也不发送。第一行为空时按钮不可用。修改字符串列表后会清空旧导出结果，请重新点击导出。可复制这条命令给其他玩家，让他们向你发密语。

例如两行分别是 `RRC-Inviteme` 和 `rrc_inviteme`：这两条密语均可触发，`RRC_Inviteme`、`rrc-inviteme`、`RRC-Inviteme ` 均无效。

邀请权限由游戏的 `C_PartyInfo.CanInvite()` 判断，包括有邀请权限的团队助理。不主动屏蔽战斗、团队副本战斗或大秘境；如果游戏将聊天内容/发送者设为 secret 或拒绝邀请，则跳过，不排队补邀。无邀请权限、已满员（小队 5 人/团队 40 人）、自身或已在队伍中的角色不邀请，不自动转换团队。

战网好友密语使用事件的发送者账号 ID 查询游戏账号，再走战网邀请接口；不会把战网显示名或 BattleTag 当作角色名。只有查询结果为在线、相同 WoW 版本且未被标记为不同区域的游戏账号才尝试邀请。好友仅在战网客户端/手机或其他游戏中在线、查询不到合适的 WoW 游戏账号时不邀请；多个客户端在线时采用接口返回的游戏账号，不向全部角色广播邀请。

公会频道监听普通公会聊天，不监听官员频道或公会成就提示。公会成员直接发送匹配字符串即可，不必发送 `/w` 命令；不协调多个 RRC 使用者同时发出的邀请。“导出密语”仍保持原有角色密语格式，不增加自动发送或公会广播。

跨服角色密语的格式是 `/w 角色名-服务器名 内容`，导出自动附带服务器名。但“找不到玩家”不一定代表离线：名称解析异常、阵营/社交关系限制等仍可能导致失败。若密语根本未送达，RRC 无法触发邀请。可尝试手动 `/inv 角色名-服务器名` 或通过战网好友组队。

参考社区报告（不代表当前客户端必然仍有该问题）：[跨服密语找不到在线玩家](https://us.forums.blizzard.com/en/wow/t/cross-realm-whisper-broken/1866933)、[跨服/跨阵营密语讨论](https://us.forums.blizzard.com/en/wow/t/whispering-players-on-other-realms/1854075)。

### 社区频道调研（2026-11-14，尚未接入自动邀请）

调研依据为暴雪 UI 源码镜像的 retail 12.1.5（70783）版本，未做游戏内社区频道实测。

- **角色社区：可以监听，有条件地邀请准确的发言角色。** 可用 `CHAT_MSG_COMMUNITIES_CHANNEL` 监听收到的频道聊天；若需要精确关联消息与作者，使用 `CLUB_MESSAGE_ADDED(clubId, streamId, messageId)`，通过 `C_Club.GetMessageInfo` 取得 `message.author`。作者 GUID 可用时，再通过 `GetPlayerInfoByGUID` 解析角色名和服务器，以 `C_PartyInfo.InviteUnit` 尝试邀请。
- **战网社区：可以监听，但账号身份不等于具体角色。** 作者信息可能只有战网账号、显示名或 BattleTag，无法据此保证确定发言时使用的 WoW 角色。若接受账号级邀请，可以另走战网账号查询与邀请流程；不能把任选的在线角色说成精确的发言角色。
- `ClubMemberInfo` 没有 `realmName` 字段，`memberId` 也不是角色名或可直接邀请的 GUID。不能仅靠社区显示名、自己服务器的默认后缀或按同名搜索来邀请。
- 当前社区聊天事件没有附加的 clubId/streamId/messageId 参数；第 12、13 项分别是 GUID、战网发送者 ID，不能把第 15–18 项当作社区消息标识。
- 社区消息和 `C_Club` 查询均受聊天 secret 限制；改用社区查询不是绕过限制的方法。只处理可读的消息和明确的身份，资料不足则跳过。不能承诺监听未订阅频道或离线期间的全部历史；后续若实现，应避免把历史回填、消息编辑当作新的组队请求。
